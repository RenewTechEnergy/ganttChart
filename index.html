Notes
• Hierarchy: Project (P) ▸ Task (P-T) ▸ Subtask (P-T-S). Edit subtask data; tasks and projects roll up automatically (earliest start, latest end, summed costs).
• Scheduled vs Actual: Scheduled dates are the plan — set when a row is created and only changed by opening the edit modal. Actual dates track what really happened (or is happening). Dragging a bar shifts actual dates only; the schedule stays put as a baseline to measure delay against.
• Predecessors: comma-separated list of IDs that must finish before this one can start (Finish-to-Start). A subtask's % Done is locked at 0 until every predecessor reaches 100% — its rolled-up parents (task, project) also stay at 0 to reflect that no work can have begun yet.
• Slack (days): how many days a subtask can be delayed without delaying the project end. Slack = 0 → critical path (★).
• Critical path: the chain of subtasks with Slack = 0 (★). Any delay on these slips the project finish — focus management attention here.
• Late Start vs Delay: Late Start = scheduled start has passed but nothing has begun (no actual_start, 0%). Delay / At Risk = work has begun and we're past the scheduled end. They never apply at the same time.
• % Done: only editable on subtasks. A task's % Done is the est_cost-weighted average of its subtasks; a project's is the weighted average of its tasks. Edit a subtask and the rollup updates immediately. (Falls back to a simple average if no est_cost is set.)
• Cost Variance = Cost-to-Date − Estimated. Negative (under budget) is good; positive (over budget) is bad.
• Margin = Sale Price − Cost-to-Date. Costs and % Done roll up from subtasks; sale price is set on the project row only.
• Row grouping: use the ▾/▸ arrows next to project/task rows to collapse subtasks, or "⊟ Collapse" in the toolbar.
• Saving: the CSV download is the session store — reload it next time by attaching the file and re-running the gantt-chart skill.
